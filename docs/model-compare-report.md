## 2. 成本差异归因（为什么 glm 贵 40 倍）

glm-5.2 的成本 = 价目表 × 用量，两个因子同向放大：

| 因子 | glm vs mimo | 数值 |
|---|---|---|
| 命中价（hit） | $0.26 vs $0.004 | **65×** |
| 输出价 | $4.40 vs $0.87 | 5× |
| miss 输入价 | $1.40 vs $0.435 | 3.2× |
| hit token 用量 | 4.0M vs 1.2M | 3.2× |
| 输出 token 用量 | 99K vs 19K | 5.2×（glm 长推理输出） |

glm 的 $1.94 里 **hit 占 $1.04（54%）**——glm 反复重放增长中的上下文，且它的命中价是 mimo 的 65 倍。用量侧 glm 也更「用力」：读源码更细、多写了 28 个 index 胶水测试、9 个自主决策、漂移表——工程产出确实更厚（BUILD-NOTES 是最完整的一份），但三份产出的**核心逻辑质量目前看相当**。

## 3. Code Mode 兼容性发现（首轮失败样本，独立记录）

首轮 glm/mimo 曾在 **code 预设（run_code TypeScript SDK）** 下运行：glm 14 次、mimo 17 次 run_code 调用全部 SDK 报错（`pwd.stdout.trim is not a function` 等），零产出、零提交。基线 flash 用标准工具。改 standard 预设后重跑成功。

**发现**：glm-5.2 与 mimo-v2.5-pro **无法驱动 dsh Code Mode**（至少在此版本 SDK 下）。这是独立的兼容性结论——若用户工作流保留 code mode，这两模型不可用；若走 standard，均可用。

## 4. 初步结论（质量盲审完成前为「方向性」）

1. **「plan 质量主导」假设得到支持**：决策完备的 plan 让三个模型都产出了全绿、规则正确的实现——模型间差异体现在过程厚度（git 节点、记录、测试数）而非核心正确性。
2. **经济结论（若盲审确认质量相当）**：此任务形态下「最便宜的够用模型」赢——mimo ≈$0.05/次 build，是 flash 的 1/3、glm 的 1/40。glm 的溢价没有兑换成可观察的核心质量差。
3. **不绑定 DeepSeek 的判据**：workflow 层（五件套/双会话/git 纪律）不依赖模型已再次验证；工具层标准模式下 flash/glm/mimo 均可跑通。

## 7. 盲审结果（2026-08-15，独立盲审员 × 匿名 A/B）

> 盲审方式：目录匿名化为 A组/B组，由从未见过原目录的独立子代理评审（规格=plan §3-§7/§9，禁止读参考实现/报告/会话日志）。dsh 会话事后揭名：**A组=glm-5.2，B组=mimo-v2.5-pro**。

| 维度 | A组(glm-5.2) | B组(mimo-v2.5-pro) | 关键差距 |
|---|---|---|---|
| 代码结构 | 5 | 4 | B 的 decision.js 直接耦合活 agent，A 纯函数解耦 |
| 单测有效性 | 5 | 4 | B 把「未知 own 键静默接受」固化为测试——弱校验被正当化 |
| 决策规则正确性 | 5 | 4 | B 对「最新事件无 usage」停止扫描取它判 hot，可能误判 |
| 信封兼容性 | 5 | 5 | 平 |
| 回退保护与边界 | 5 | 3 | B 用 JSON.stringify 粗估算；cold 路径**忽略 modelPolicies 对 summarizationProvider/Model 的覆盖**（违反 §6.2） |
| 文档与记录 | 5 | 2 | A 有完整 BUILD-NOTES（D1-D5、9 个自主决策、漂移表）+ 6 节点提交；B 无文档、2 个概括提交 |

**B 组实质缺陷**：① cold 路径不尊重 modelPolicies 的 summarization* 覆盖（`lib/index.js:236-239`）；② 转录渲染偏离 §6.1（`[user] [tool result]` 双重标签、嵌套括号）；③ own 键弱校验；④ 决策取「无 usage 的首个匹配」。
**结论：A 组（glm-5.2）整体明显优于 B 组（mimo-v2.5-pro）**；B 的三处缺陷都在其 73 个全绿测试的盲区之外——「测试全绿 ≠ 正确」。

## 8. 终局结论（三方综合）

| 模型 | 质量（盲审+基线评审） | 成本/次 build | 性价比判定 |
|---|---|---|---|
| deepseek-v4-flash（基线） | 高（61 测试、5 处偏离全为正确修正） | ≈$0.14 | **最优** |
| glm-5.2 | 高（略胜基线：文档/防御性/忠实度全满分） | ≈$1.94（14×） | 溢价未兑换核心正确性优势 |
| mimo-v2.5-pro | 中（三处契约违反，测试盲区） | ≈$0.05 | 最便宜但「够用」存疑，需人工修复+复审 |

1. **plan 质量主导再次验证**：同一份 plan，三个模型都能产出可运行实现——但「可运行」≠「合格」，质量分层真实存在。
2. **不绑定 DeepSeek 的裁决：维持绑定**。flash 在质量≈glm 的情况下便宜 14 倍；glm 的溢价买的是过程厚度（文档、防御性），不是核心正确性；mimo 便宜但需要人工修复投入，综合成本未必低。
3. **盲审价值实证**：mimo 73 测试全绿仍藏三处契约违反——「单测全绿」是最弱的验收证据，「对照计划盲审」才是真门槛。此结论回写工作流模板（验收补充）。
4. **二轮建议：跳过 kimi-k3**。旗舰档问题（贵是否更好）已被 glm 数据回答：更好但只限于过程层、14 倍价。若仍想补一个协议干净的旗舰样本再定夺，kimi-k3 是唯一候选（openai 协议），预期 ≈$5/次；收益/成本比低，不推荐。

**建议**：先盲审首轮。若三份质量相当 → 二轮只测 kimi-k3（唯一 openai 协议的旗舰档）或不测；若质量有分层 → 按分层结论补测对应档位。
